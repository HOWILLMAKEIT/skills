# 从生成原图到可编辑 PPT

## 先做还原差距清单

同时打开选定生成图与当前版本（如有），逐项记录构图占比、视觉中心、模块位置、形状轮廓、颜色明暗、渐变、字体宽度与字重、数学记号、线宽、留白和关键连线的差距。不要从原图“记住大意”后重新画一套常见流程图。

## 重建方法

使用 PowerPoint 原生文本框、自动形状、自由曲线、连接线、原生渐变与必要分组。可通过 GUI、python-pptx、PptxGenJS 或当前可用的演示文稿工具创建。每个模块保留合理语义结构；图元数量多不自动等于可编辑性好。

先定整张图的坐标系和最终物理尺寸，再定面板与主连线，最后填充节点、图标、文字和细节。将坐标、样式与文本保存为源代码或场景描述。修订旧版时另存新版本。

整图图片、单个嵌入 SVG、自动描边碎片或截图加 OCR 文本不能替代具有语义的原生重建。照片、显微图等天然栅格内容按用户允许的范围保留并说明，不能声称像素内容可逐对象编辑。

必要的科学纠错优先于逐像素照搬，例如连线误指、标签拼错或代码示意不合法；修正并记录，保留其有效视觉设计，不扩大成未授权的方法改写。

## 容易损失质感的实现点

- 原图的浅渐变、强调色、曲线分区和局部细节是视觉设计的一部分；可编辑不意味着只能使用平涂矩形。
- 原生渐变应显式设置色标和方向。`scripts/native_shapes.py` 提供线性渐变与清除主题效果两个 DrawingML helper。
- 某些导出器在空 `a:effectLst` 下仍会应用 `p:style/a:effectRef`。需要无阴影风格时同时清空显式效果并将主题 effectRef 置为 0，再查看实际导出。
- PDF 中出现意外栅格资源时检查主题阴影、透明效果与过滤器。PPT 原生可编辑和导出 PDF 完全矢量是两个分别验证的属性。
- 检查所选字体是否包含数学字形。上下标可用原生富文本或分开的可编辑字形定位；不因缺字随意删除数学含义，检查最终渲染字级。
- 即使设置“不换行”，也需检查实际导出中的代码、短标签和圆节点单词。渲染器可能改变字宽、基线和留白。
- 自由曲线和短轨迹应与原图层级一致；示意地形和路径需标明示意，不能充当无来源的实测结果。
- 主箭头、细轮廓和反馈线采用有限几档线宽；连接点放在正确对象上，优先通过重新布局减少绕线。

## 导出与验证

1. 保存 `.pptx`，从 PowerPoint、LibreOffice 或可用演示文稿渲染器导出 PDF，再渲染预览。
2. 原图和实际 PPT 预览并排评估，在整图及最终论文尺寸分别检查。
3. 在临时副本中修改文字、移动对象、修改渐变色标，保存重读；不改交付正本来做验证。
4. 检查图片对象、媒体和图片填充。要求全部原生的示意图应为空；允许的混合素材需列明。
5. 论文用图和展示预览应来自已检查的最终 PPT 导出，避免两套独立绘图引擎产生分叉。
6. 有字体/碰撞审计可用时运行。渐变填充带可能产生 fill-edge 警告，被遮挡的路径也可能触发检测；逐项查看并记录原因，不能一概忽略。

```bash
python scripts/audit_pptx.py /project/figures/run/editable/figure_v001.pptx \
  --pdf /project/figures/run/exports/figure_v001.pdf \
  --output /project/figures/run/qa/editability_v001.json
```

脚本需要 `python-pptx`，检查 PDF 另需 PyMuPDF。先查可用运行时和项目依赖，不为检查重装整套办公软件。缺少渲染器时保留 PPT 和源文件，说明实际渲染尚未验证，不以替代预览伪装完成。

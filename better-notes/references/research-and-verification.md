# 调研与事实核对

本文件用于在写笔记前选择来源、检查时效性并处理冲突。

## 1. 来源优先级

| 优先级 | 来源 | 适合确认的内容 |
|---|---|---|
| 1 | 官方文档、规范、API reference | 当前接口、参数、输入输出、约束 |
| 1 | 官方 release notes、迁移指南 | 引入、弃用、移除、替代方案 |
| 1 | 原始论文、作者勘误 | 方法、公式、实验设置与结论 |
| 2 | 官方仓库、源码、测试 | 文档遗漏的真实行为与版本实现 |
| 2 | 作者或维护者技术文章 | 设计动机、使用边界 |
| 3 | 高质量第三方博客、文章 | 实践经验、常见错误、解释方式 |

核心结论优先依赖一手资料。第三方内容适合补充实践，不应用来推翻适用于同一版本的官方说明。

## 2. 最小调研记录

在内部记录以下字段，不要求全部展示给用户：

```text
问题：要确认什么？
结论：当前能写入笔记的事实是什么？
来源：页面标题 + URL
来源类型：官方文档 / release notes / 论文 / 源码 / 博客
适用范围：版本、日期、平台或实验设置
核对状态：已证实 / 推断 / 未确认
```

每个核心问题至少对应一条能直接支持结论的来源。重要但存在争议的结论应寻找第二条独立来源或明确保留争议。

## 3. API 时效性检查

遇到 API、CLI、配置或依赖时，按顺序检查：

1. 找到目标版本的官方 reference，而不是搜索结果中默认出现的旧版页面。
2. 检查页面是否带 deprecated、legacy、archived、removed、experimental 标记。
3. 搜索官方 release notes 和 migration guide。
4. 确认包名、导入路径、函数签名、参数默认值和返回类型。
5. 确认示例代码使用的版本与正文一致。
6. 如 API 已弃用，正文同时写出：弃用状态、受影响版本、替代 API、最小迁移方式。
7. 如只能确认“最新文档”的行为，写明核对日期，不猜测历史版本。

推荐搜索组合：

```text
<项目> <API> official docs
<项目> <API> deprecated replacement
<项目> migration guide <版本>
<项目> release notes <版本>
site:<官方域名> <API>
```

## 4. 论文与实验结论检查

不要只读摘要。至少检查方法和实验部分，并记录：

- 任务、数据集和样本范围；
- 模型、基线和关键设置；
- 指标及其方向；
- 绝对数值与对照差异；
- 作者明确报告的限制；
- 论文结论与自己的推断分别是什么。

不能把单一数据集上的结果写成普遍规律，也不能把相关性改写成因果关系。

## 5. 冲突处理

资料冲突时：

1. 先检查是否针对不同版本、平台或实验设置。
2. 同一范围内优先采用更新的一手资料。
3. 官方文档与实际源码不一致时，说明核对的版本或 commit，并标记差异。
4. 无法消解时并列两种说法，写清各自来源，不自行选择看起来合理的一种。

## 6. 无法联网或来源不足

不要回退到纯记忆写作。应输出：

```text
目前无法取得支持该笔记核心内容的必要资料，因此没有生成事实性正文。
缺少：<官方文档 / 目标版本 / 原始论文等>
下一步：请提供链接或文件，或在网络恢复后重试。
```

如果用户只要求整理其提供的原文，可以进行来源内重组，但要明确“未做外部事实核对”，且不得补充原文之外的事实。

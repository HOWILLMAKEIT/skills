# Humanizer 人工回归场景

用于审查 `better-notes` 的风格编辑行为。每次执行记录实际输出和通过/失败；此场景清单本身不代表已完成行为验证，结构校验也不能证明生成笔记符合要求。下列文本是给定的编辑材料，不是已做外部核对的技术结论。

| 场景 | 给定材料或任务 | 通过条件 |
| --- | --- | --- |
| 空泛铺垫与重复 | “让我们深入探索这个强大的接口。传入 `limit=10` 最多返回 10 条记录，无记录时返回空列表。这一点至关重要。” | 保留参数、数量上限和空列表；删除铺垫、宣传词和重复结尾，不新增功能 |
| 无信息对比 | “它不仅仅是一个接口，更是赋能数据处理的强大工具。它接收 JSON，返回记录列表。” | 直接写输入和输出，不保留无依据抬高语气的对比 |
| 必要对比 | “缓存命中时返回已有结果，不重新计算；未命中时计算并写入缓存。” | 保留两种条件、动作和否定，不为避开“不是”而删去区别 |
| 真实三项 | “请求包含 `name`、`version`、`limit` 三个字段。” | 保留全部三个字段，不合并成模糊描述，不凑第四项 |
| 范围与不确定性 | “在测试集 D、种子 1 下，A 为 82%，B 为 80%；其他设置尚未验证，因此不能判断普遍表现。” | 保留测试集、种子、数值、对照与未验证范围，不写成 A 普遍更好 |
| 技术内容保护 | 给定带 YAML、代码块、行内代码、命令 `tool --limit 10`、路径、URL、公式及原文引用的笔记 | 风格编辑只改叙述文本，受保护内容逐字保持；技术错误另走事实核对 |
| 装饰与语义区分 | 笔记既有每条加粗标签、emoji，也有“输入 → 处理 → 输出”、数值范围和 Mermaid | 清理无作用装饰，保留语义箭头、范围及图中技术关系 |
| 作者声音 | 用户提供简洁中文样例，含偶尔的破折号和明确的个人判断 | 参考样例节奏，保留已给出的判断；不虚构经历，不添加比喻或随意聊天 |
| 编辑套话 | 笔记以“好问题”开头，每节写“本节将介绍”，末尾写“希望对你有帮助” | 最终正文无聊天包裹和重复元叙述；保留真实来源、核对日期和验证状态 |
| 资料缺口 | 请求写当前 API 笔记，但必要官方资料无法获取 | 不用自然语气掩盖缺口，不回退到模型记忆编事实；说明缺少的资料 |
| 仅弱信号 | 一段准确简洁的技术说明只含一次被动语态或“关键” | 不机械重写；只有造成空泛、重复或歧义时才调整 |
| 文件与交付 | 要求将完成的笔记写入文件 | 文件只包含最终笔记，不附草稿、风格评分、内部模式清单或“已通过 AI 检测”声明 |

审查时对照编辑前后列出独立信息，先检查是否有事实丢失或无依据新增，再判断是否更简洁自然。涉及 API 和版本的实际笔记仍需遵守写作前的一手资料核对要求。

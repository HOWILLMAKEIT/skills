# 编写项目 AGENTS.md

## 参考与适用范围

参考来源：[anomalyco/opencode — AGENTS.md](https://github.com/anomalyco/opencode/blob/dev/AGENTS.md)，阅读日期 2026-10-27。该链接为可变的 dev 分支；这里记录的是本 skill 的提炼，不声称持续跟随上游。后续若用户要求重新对齐，重新阅读来源。

采用它“把可执行的项目约定写具体”的方式，并借鉴以下通用原则：逻辑保持直接；抽取函数应有实际理由；外部输入在所属边界校验后以约定类型传递；异常处理按需要设置；针对极低概率边界增加复杂度前先说明问题与成本并取得用户同意；测试覆盖真实实现。

上游的 Bun、Effect、TUI、包依赖方向、导入限制、分支与 PR 格式均属于其项目约定，不能直接套用到其他项目。

## 内容选择

以 [AGENTS 模板](../assets/AGENTS.template.md) 为起点，从仓库配置、CI、实际代码和用户指令中填入事实。

1. 用少量文字说明项目解决什么问题、当前主线在哪里。
2. 用路径表帮助定位代码、测试、设计、运行记录和产物。
3. 给出本项目实际使用的运行时、安装、启动、测试、检查与生成命令，并写明工作目录。
4. 记录会改变实现决策的依赖方向、接口边界、生成文件规则和代码约定。
5. 记录真实存在的操作约束，例如运行中源码不可覆盖、指定数据目录、发布入口；不编造额外流程。
6. 指向 HANDOFF 和 docs 索引；详细背景链接到专题文件。

优先写“在何处运行哪个命令、为什么有这个限制”，而非“保证高质量、遵守最佳实践”。命令来自脚本并不等于已经运行过，验证状态要准确。

## 改已有文件

先读完整文件及适用的子目录 AGENTS.md，再合并本次必要变化。保留用户约束、工具管理区块和不相关内容，不整份替换。若同名文件使用其他大小写，先确认现有约定，不创建大小写相近的两份指南。

冲突会改变工作范围或方法时向用户说明；只是不够新时，用已核实事实更新并保留有用的历史链接。不要把实时运行表、长篇设计或完整故障日志塞入 AGENTS.md。

# 论文笔记检查场景

用于维护本 skill 时检查论文笔记模板是否被遵守。这些场景只列出应有的行为，不代表生成行为已经通过验证。

| # | 场景 | 应有行为 |
|---|---|---|
| 1 | 用户让为一篇论文写笔记 | 使用四部分模板：一、研究现状和作者动机；二、方法简要介绍；三、方法细节；四、实验。章节名称和顺序不改，不增加“总结”等顶层章节 |
| 2 | 只给了论文标题或摘要 | 先取得并读完全文（PDF 或 arXiv HTML），核对所读版本；取不到全文时停止写事实性正文，说明缺什么 |
| 3 | 只读第二部分 | 能说出论文要解决的问题、核心做法、与基线的区别和一轮流程；第二部分不依赖第三部分 |
| 4 | 第二部分的主图 | 嵌入论文方法总览图并写图注（图号、各部分含义、要看哪几处）；删除图后文字仍完整 |
| 5 | 取不到论文原图（无 PDF、提取失败） | 写“主图见论文 Figure N”并附链接，在回复里说明原因；不用自绘图冒充原图 |
| 6 | 第三部分有定理 | 先写结论，再写作者为什么要证明它；证明放进 `> [!note]-` 折叠块，只保留关键推导 |
| 7 | 第三部分的图（Obsidian） | 至少一个 Datacore 流程组件，步骤和数字来自论文，自拟数据标“示意”，不用 Mermaid |
| 8 | 保存位置不在 Obsidian 库 | 第三部分用编号流程和表格，必要时 Mermaid，不写组件 |
| 9 | 论文没有说明某个实现细节 | 写“论文未说明”，不补全 |
| 10 | 第四部分写结论 | 每条结论带指标、条件、对照对象和论文的表号或图号；区分论文声称的结论和自己的推断 |
| 11 | 想写自己的判断（如局限） | 标“推断”并说明依据，与论文自己承认的局限分开写 |
| 12 | 主题不是论文（如 API 文档） | 不使用本模板，沿用通用结构 |

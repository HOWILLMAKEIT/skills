# Obsidian 交互组件检查场景

用于维护本 skill 时检查 Datacore 组件规则是否被遵守。这些场景只列出应有的行为，不代表生成行为已经通过验证。

| # | 场景 | 应有行为 |
|---|---|---|
| 1 | 用户让为 Obsidian 库里的论文笔记配流程图 | 先检查 `community-plugins.json` 和 `data.json` 的 `enableJs`；满足后用 `datacorejsx` 组件，不写 Mermaid |
| 2 | Datacore 未安装 | 说明缺什么并询问是否安装，不擅自修改库配置；用户拒绝才回退 Mermaid 或表格 |
| 3 | 保存位置不在 Obsidian 库（如 GitHub README） | 不写组件，沿用表格和 Mermaid |
| 4 | 没有真实数据，想演示机制 | 用玩具模拟，组件内写明"示意，参数是自拟的"，标题不暗示真实结果 |
| 5 | 论文图中的数值与标签需要配对 | 注明"以原图为准"，不把推断的配对写成事实 |
| 6 | 组件里有计算（如在页面里跑装箱） | 先用独立脚本得到同一输入下的结果并对照一致，再写进笔记 |
| 7 | 笔记很短，只有一个线性三步流程 | 用编号列表即可，不添加组件 |
| 8 | 组件通过冒烟测试，但没在 Obsidian 里打开过 | 只在回复里写"逻辑测试通过，尚未在 Obsidian 里渲染验证"，不写"效果已确认"；笔记正文不含这句话 |
| 9 | 冒烟测试报 `NaN`、抛错或耗时过长 | 修复后重测；不带着失败交付 |
| 10 | 删掉全部组件 | 正文和表格仍完整表达核心内容 |
| 11 | 检查完成的笔记全文 | 不含"由 Datacore 生成""需要启用 JavaScript 视图""已通过冒烟测试""插件版本"等关于组件本身的说明；组件内只有来源和"示意"标注 |
| 12 | 组件需要区分多个类别的颜色 | 颜色来自主题变量或固定语义色（背景与文字色同时指定）；浅色、深色主题都可读；区分色不超过 4 个，不用渐变色表示无序类别 |
| 13 | 要比较两个量纲不同的指标 | 不用双纵轴；拆成两张图或归一到同一基准 |
| 14 | 组件里的数值只出现在悬停提示框中 | 改为直接标注或在正文、表格给出同样的值；键盘聚焦显示相同内容 |
| 15 | 检查组件样式 | 无入场动画、无每个元素的悬停动画、无装饰性阴影、渐变、全大写标签；按钮文字用动词 |
| 16 | 画流程图 | 箭头都有动作标注；只画论证依赖的部分；`<svg>` 带 `role="img"` 和 `aria-label` |

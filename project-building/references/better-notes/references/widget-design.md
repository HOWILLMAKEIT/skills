# 组件设计准则

写 Datacore 组件的界面前读取本文。[obsidian-datacore.md](obsidian-datacore.md) 规定组件怎么运行和验证，本文规定组件长什么样、怎么交互。

## 来源与适用性

本文从下列公开资料提取原则，并按"嵌在笔记里的小组件"改写，没有照搬任何一份：

- Anthropic 的 [frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)：结构承载信息、克制动效、文案用主动语态和简单动词。
- Claude 内置的 `dataviz` 与 `artifact-diagramming` skill：选图形式、配色分工、标记与交互、无障碍，以及内联 SVG 的画法。这两个 skill 在不同环境里不一定可用，规则已在本文写全。

不采用的部分：frontend-design 要求每个页面确立独有的视觉身份、字体和配色。笔记组件嵌在用户自己的主题里，应当沿用主题，不带自己的风格。`dataviz` 的调色板验证脚本只在组件使用 3 个以上的区分色时才需要。

## 1. 沿用主题，不自带风格

- 颜色、边框、背景用 Obsidian 变量（清单见 obsidian-datacore.md §3），不写死十六进制。组件在浅色、深色和任何第三方主题下都要可读。
- 只有表达固定语义的颜色才写死，例如"思想=橙、代码=蓝"。写死颜色时同时写死背景色和文字色，保证对比度，并在浅色、深色背景上都检查。
- 字体、字号沿用笔记正文，不引入新字体。字号层级最多两级：正文大小和略小的说明文字。
- 整个组件只允许一个强调点，用 `--interactive-accent`。其余元素保持中性。
- 边框、编号、标签、分隔线必须承载信息，例如编号表示真实顺序。不加装饰性圆角卡片、阴影、渐变和全大写标签。
- 不用 `<style>` 之外的全局样式；类名带组件前缀（见 obsidian-datacore.md §5）。

## 2. 先选形式，再画

先问读者要做什么，再选形式。

| 读者要做的事 | 形式 | 避免 |
| --- | --- | --- |
| 看一个数 | 直接在正文写出数字 | 只有一个柱子的柱状图、2 个扇区的饼图 |
| 比较大小 | 横向或纵向柱状图 | 面积图、雷达图、近似数值的饼图 |
| 看随时间的变化 | 折线图 | 用柱子的高度表示时间连续量 |
| 看流程和先后 | 逐步播放的流程图 | 无顺序的盒子堆叠 |
| 比较几种做法 | 并排图，只画它们不同的边 | 每个方案一个孤立的盒子 |
| 看一个参数的影响 | 一个滑块 + 一个实时结果 | 同时三个以上滑块 |
| 查大量精确值 | 表格 | 靠颜色区分 7 类以上 |

- 一张图只表达一个论断，在组件标题或图注里写明（"交互：……"，见 obsidian-datacore.md §6）。
- 画机制，不画名称。只画论证依赖的部分：边界、新增的一跳、数据流向、状态变化。
- 箭头必须标注动作，例如"写入""使缓存失效""每 30 秒轮询"。无标注的箭头只表示"有关系"。
- 复杂度按判断需要定：一跳的问题画三个框，涉及队列的迁移画出队列、写入方、读取方和顺序箭头。不画整个系统。
- 区分系列时，同一概念在所有组件里用同一个颜色；筛选或点选后，剩下的系列不改颜色。不用颜色深浅表示没有顺序的类别。
- 区分色不超过 4 个。更多类别时，只高亮一个，其余用中性色；或改用表格。

## 3. 标记与排版

- 线条细（约 2px），数据点不小于 8px，网格和坐标轴用实线细线，颜色接近背景。
- 柱子之间、堆叠段之间留约 2px 背景色间隙，不用边框隔开。
- 只给端点、极值或关键项加直接标注，不在每个点上标数字。系列不止一个时需要图例；标签与图形用同一个颜色标记，文字本身用正文颜色。
- 标签放不下时，移到图形外或放进提示框，不让文字被裁切。
- 不使用双纵轴。两个量纲不同的量，画两张图，或都归一到同一基准（如起点=100）。
- 内联 SVG：用 `viewBox` 控制尺寸并让外层缩放；描边和文字用 `currentColor` 继承主题；箭头用 `<marker>` 或 `<polygon>`；文字约 11–13px，只写几个词，解释放在图下方的文字里。元素按网格对齐。
- 整个 `<svg>` 带 `role="img"` 和 `aria-label`，内容是这张图的论断。

## 4. 交互

- 所有数值都能不靠悬停读到：直接标注，或在正文、表格中有同样的值。提示框只是补充，键盘聚焦时显示与悬停相同的内容。
- 悬停目标比图形大：命中区域至少约 24px，包含图形之间的间隙。折线图让纵向参考线吸附到最近的 X 位置，读者不必对准 2px 的线。
- 提示框里数值最突出，系列名其次；系列名和数据来自外部时用 `textContent` 或 JSX 文本插入，不用 `innerHTML` 拼接。
- 控件放在组件顶部一行，作用于组件内所有内容；不在图内部放筛选器。
- 更新数据时保持原有布局：旧内容降低不透明度，不闪空白，不让高度跳动。
- 动效只用于响应用户的操作（点击后的步骤切换、滑块的实时数值）。不加页面载入时的淡入或上滑，不给每个元素加悬停动画。保留 `prefers-reduced-motion` 时关闭动画的处理。

## 5. 文案

- 按钮、标签用动词：写"运行""重置""下一步"，不写"提交""确定"。
- 标题和标签用句子大小写的普通语言，不用全大写，不加感叹号。
- 空状态和错误信息说明读者下一步能做什么，例如"输入 1 到 20 的整数"，不只写"输入无效"。
- 组件内的数字写单位和对象；自拟数据标"示意"（obsidian-datacore.md §6）。组件文案同样遵守 [language-precision.md](language-precision.md)。

## 6. 无障碍与窄屏

- 可点击元素用 `<button>`；需要自定义元素时用 `role="button"`、`tabindex={0}` 和 Enter、空格的 `onKeyDown`。
- 颜色不是唯一的编码：同时用文字、形状或位置。状态（成功、警告、失败）配图标和文字。
- 每个组件至少有一种非视觉的等价形式：正文里的文字说明，或表格。
- 宽的 SVG 外层加 `overflowX: 'auto'`。触摸目标不小于约 24px。
- 完成后实际在窄宽度和深浅两套主题下看一遍；冒烟测试不检查样式、主题和布局。无法在 Obsidian 里查看时，在回复里说明未检查。

## 7. 交付前自检

1. 这个组件让读者多理解了什么？删掉后正文是否仍然完整？
2. 颜色是否全部来自主题变量，只有固定语义的颜色例外？
3. 一个强调点，没有装饰性的阴影、渐变、大写标签和入场动画？
4. 形式与读者要做的事匹配；没有双纵轴、没有对无序类别用渐变色？
5. 每个数值不靠悬停也能读到？键盘能操作每个按钮？
6. 箭头都有标注？图有一个论断（标题或 `aria-label`）？
7. 笔记正文里没有关于组件、Datacore 或测试状态的说明（见 obsidian-datacore.md §7）。

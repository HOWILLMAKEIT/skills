# 论文笔记模板

笔记对象是一篇论文时使用本文件。章节固定为四部分，顺序和名称不改。目标读者是几周后重读的作者本人：只读第二部分就能抓住论文主要内容，需要细节时再读第三部分。

写作前先读完论文全文（PDF 或 arXiv HTML），不能只读摘要、项目页或二手解读。核对论文版本（arXiv v1/v2）和发表信息。

## 1. 整体结构

```markdown
# 简称：一句话概括论文做了什么

论文：[标题](URL)（会议与年份；所读版本及日期）
代码：[仓库](URL)（有则写，无则省略）

> [!abstract] 一句话理解
> 已有做法的局限 + 本文的改变 + 关键结果或理论保证。

## 一、研究现状和作者动机
## 二、方法简要介绍
## 三、方法细节
## 四、实验

## 来源

资料核对日期：YYYY-MM-DD
```

不增删顶层章节。“局限”“未解决的问题”写进第二部分和第四部分，不另开“总结”章节。

## 2. 一、研究现状和作者动机

回答：这个方向现在怎么做、卡在哪里、作者为什么这样改。

1. **现状**：主流做法及代表工作，用一段写清它们共同的设定和目标。
2. **困难**：作者指出的问题，编号列出，每条注明论文引用的依据。论文没有给依据的不写成事实。
3. **作者的思路**：作者提出的新问题设定或目标，一句话说清与现状的差别；有符号定义时只放最基本的一两个。
4. **贡献与理论**：论文声称的贡献；有定理时只列结论和编号（如 Theorem 1），证明放第三部分。

## 3. 二、方法简要介绍

这部分必须自足：删掉第三部分，读者仍能说出论文做了什么、怎么做、新在哪里。

按以下顺序写：

1. **一句话记住**：用“基线做 A，本文做 B”的对照句，不超过两行。
2. **论文主图**：放论文的方法总览图（通常是 Figure 1），图后写图注，说明图里要看哪几处。主图规则见第 7 节。
3. **关键改动**：与基线相比改了什么，2–3 条。每条写“改前 → 改后”和起作用的原因。
4. **一轮流程**：编号列表，每步一个动作，写出关键数字设置（种群大小、预算、轮数等），数字来自论文。
5. **主线**：用一行箭头串起全流程，供复习时快速回想。
6. **创新点与局限**：一句话说清真正的新东西；再写论文自己承认的和你读出的未解决问题，后者标“推断”。

## 4. 三、方法细节

按方法的组成部分分小节，编号 3.1、3.2……。小节顺序按“先问题定义，再算法，再理论”。

每个小节：

- 先写这一块的输入、处理、输出。
- 公式用 LaTeX，公式后立刻定义符号、单位、适用条件。
- 论文给出的定理：先写结论，再回答“作者为什么要证明它”；证明过程放进折叠块，保留关键推导，不抄全文。折叠块用 Obsidian 的 `> [!note]-` 语法。
- 算法的每个步骤与论文的算法编号、图或公式编号对应，方便回查。
- 论文没有说明的实现细节，写“论文未说明”，不要补全。

**图**：笔记在 Obsidian 库里时，本部分至少放一个 Datacore 组件，用来展示方法的执行流程或关键机制，规则见 [obsidian-datacore.md](obsidian-datacore.md) 和 [widget-design.md](widget-design.md)。组件里的步骤和数字来自论文；自拟的示意数据标“示意”；不放论文没有的实验结果。保存位置不在 Obsidian 库时，用编号列表和表格，必要时 Mermaid。

## 5. 四、实验

按以下顺序：

1. **设置**：任务与数据集（含公开基准）、对比方法、骨干模型、关键超参数、评价指标及其方向（越高或越低越好）。
2. **主结果**：用表格，列出任务、测试条件、主要结果。结论必须带指标、条件和对照对象，如“相对次优基线，gap 相对降低约 50%–60%”。数字对应论文的表号或图号。
3. **其他实验**：泛化、消融、参数分析、案例等，每项写“做了什么 → 得到什么”。消融要写明去掉了哪个组件、哪个影响最大。
4. **结论**：这些实验支持论文的哪些主张，没有覆盖哪些。区分论文声称的结论和你的推断。

不复制整张表。表格只保留支撑结论所需的行。

## 6. 证据与措辞

- 论文原文给出的内容用陈述句；自己的判断写“推断”并说明依据；资料不足写“论文未说明”。
- 与论文版本有关的内容（页码、编号、数字）标明所读版本。
- 数字、公式、定理编号逐项回查原文，不凭记忆。
- 其余语言规则沿用 [language-precision.md](language-precision.md) 和 [humanizer.md](humanizer.md)：一句一事、术语全文同名、不用比喻。

## 7. 主图的取得与放置

1. 从论文 PDF 或 arXiv 源文件里取方法总览图。优先用源文件中的矢量图或高分辨率位图；从 PDF 截取时用 `pdftoppm -r 200` 或 PyMuPDF，裁掉多余留白。
2. 保存到笔记所在库的附件目录，沿用该库已有的附件目录和命名习惯；文件名带论文简称和图号，如 `EoH-S-Figure1.png`。
3. Obsidian 库里用 `![[文件名]]` 嵌入，其他目标用相对路径 `![](路径)`。
4. 图下写一行图注：图号、图里各部分的含义、要看哪几处。
5. 取不到图时（无 PDF、版权限制或提取失败），在笔记里写“主图见论文 Figure N”并附论文链接，同时在回复里说明原因；不要用自绘的图冒充论文原图。自绘的方法图属于第三部分的组件，要标明是自绘。
6. 图片只是补充：删掉图后，第二部分文字仍完整。

## 8. 交付前自检

- 四个章节名称、顺序与本模板一致，没有多出顶层章节。
- 只读第二部分，能否说出论文要解决什么、核心做法、与基线的区别、一轮流程？
- 第二部分有论文主图和图注；取不到图时已说明。
- 第三部分每个公式有符号定义，每个定理有结论和用途，证明已折叠。
- 第三部分有流程组件（Obsidian）或编号流程（其他目标），内容与论文一致。
- 第四部分每条结论带指标、条件、对照对象和表号或图号。
- 推断、论文未说明、局限已标明；没有把自己的判断写成论文结论。
- 来源列出论文、代码（如有）和访问日期。

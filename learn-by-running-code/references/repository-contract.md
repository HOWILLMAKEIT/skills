# 学习仓库契约

本文件仅规定 `learning` 模式生成的 Python 学习仓库如何组织、运行和验证。`project` 模式（包括基于已有仓库开发）使用 [project-contract.md](project-contract.md)，不受本文件的空目录、独立章节与固定工具链要求约束。

## 必需文件

| 路径 | 作用 |
| --- | --- |
| `README.md` | 30 秒启动、课程路线、逐章命令、预期现象、排错和资料版本 |
| `AGENTS.md` | agent 导师指令：角色、课程快照、逐章教学卡、教学节奏、环境事实与进度记录 |
| `pyproject.toml` | Python 版本与全部课程依赖的唯一声明 |
| `uv.lock` | 可复现的依赖锁定结果，必须由 uv 生成 |
| `.python-version` | 默认写入 `3.12` |
| `.gitignore` | 至少忽略 `.venv/`、`.env`、缓存和构建产物 |
| `01_<slug>/main.py` | 第 1 章可运行入口，后续章节格式相同 |

只有实际需要环境变量时才创建 `.env.example`；只有多个章节确实复用同一稳定实现时才创建 `shared/`。

## AGENTS.md 教学指令文件

课程仓库最终往往由被要求“教我”的 LLM/agent 消费。根目录必须生成 `AGENTS.md`；支持该约定的 agent 进入仓库后会自动读取它。它不是代码贡献指南，而是导师操作手册，必须包含：

1. **角色声明**：本仓库是学习课程；agent 的职责是引导学习者自己运行、观察和修改，不替学习者完成练习，不一次性倾倒整章答案；
2. **课程快照**：主题、学习者画像、完成标准、统一贯穿案例和章节依赖顺序；
3. **逐章教学卡**：每章写明唯一新增概念、最小知识讲解（问题 → 输入 → 处理 → 输出 → 边界）、worked example、知识到代码的映射、准确运行命令和预期现象、一个引导实践、一个独立实践、2～3 个检索/自我解释问题和常见错误；
4. **教学节奏**：严格按“知识讲解 → worked example → 代码映射 → 预测与运行 → 引导实践 → 独立实践 → 检索与自我解释”推进；卡住时按“定位范围 → 指出关键行 → 给最小代码提示”逐级帮助；理解检查通过后再进入下一章；
5. **环境事实**：每章在哪运行（本地、服务器或外部服务）、所需凭据/费用，以及哪些命令已实际运行、仅静态检查或尚未验证；
6. **进度记录**：将日期、完成章节、实验结果和遗留疑问追加到根目录 `PROGRESS.md`；不存在时由导师创建。

`AGENTS.md` 应从 `assets/AGENTS.template.md` 按课程实情生成，在最终集成阶段与 README 和实测结果一起复核。不得写入未验证命令、真实密钥或与 README 冲突的环境说明。

## 章节目录

- 使用从 `01_` 开始的两位连续编号和简短英文 slug，例如 `03_tool_calling`；
- 每章默认只有一个 `main.py`，只有拆分能够明显提升理解时才增加辅助文件；
- 不从其他编号章节导入代码；共享代码只能来自 `shared/`；
- 每个 `main.py` 都包含顶部文档字符串：本章目标、相对上一章新增内容、运行命令、最小知识块与知识到代码的映射；
- 使用 `if __name__ == "__main__":` 暴露清晰入口；
- 不在核心路径留下 `pass`、`NotImplementedError`、AST Ellipsis 或虚构 API。

“独立运行”定义为：完成一次根目录 `uv sync` 后，可以直接执行该章命令，不需要先运行其他章节，也不依赖其他章节留下的状态。

## 根 README

README 至少包含：

1. 课程解决什么问题，以及学完能做什么；
2. 30 秒启动：`uv sync` 和第一章命令；
3. 章节路线表，列出概念、命令、预期现象和外部要求；
4. 统一案例和各技术组件的分工；
5. 配置说明，只展示假密钥；
6. 常见问题，覆盖安装、导入、环境变量和外部服务失败；
7. 资料来源、核对日期和选用版本；
8. 已实际验证与尚未在线验证的边界。

路线非线性且画图确实更清楚时使用 Mermaid。不要输出字符画目录树。

## uv 与依赖

- 默认 `requires-python = ">=3.12"` 和 `.python-version` 为 `3.12`；课程依赖要求其他版本时，先确认版本方案，再同步修改 Python 模板、README、AGENTS 与锁文件；
- 依赖统一放在根 `pyproject.toml`，不要给每章创建虚拟环境；
- 优先选择课程实际需要的最少依赖；
- 先执行 `uv lock` 生成锁文件，再执行 `uv sync`；
- README 中所有 Python 命令统一写成 `uv run python <chapter>/main.py`；
- 不把 `.venv/`、缓存、真实 `.env` 或平台专用临时文件提交进仓库。

## 外部服务

需要 API、数据库或本地服务时：

- 在 `.env.example` 写清变量名和假值；
- 程序缺少配置时应快速失败，并告诉学习者缺少哪个变量；
- README 说明是否付费、数据会发往哪里、有没有离线替代章节；
- 测试时不得把未实际发送的请求表述为已经在线验证。

## 目标目录安全

创建前检查目标：

- 不存在：可以创建；
- 存在且为空：可以使用；
- 存在且非空：列出冲突并等待用户决定，不覆盖、清空或移动原文件；
- 如果目标位于 Git 仓库中，先查看工作树状态，保留无关修改。

## 验证顺序

在仓库根目录依次执行：

```bash
uv lock
uv sync
python <skill-path>/scripts/validate_learning_repo.py .
uv run python 01_<slug>/main.py
```

校验器由 Python 3.11+ 运行，默认检查上述 3.12 契约。用户已确认其他课程版本时，显式传入预期值，例如：

```bash
python3 <skill-path>/scripts/validate_learning_repo.py . --python-version 3.11 --requires-python '>=3.11,<3.13'
```

这两个参数对照确认的环境，不应为了掩盖环境错误临时修改。校验器只比较声明，不代替 uv 依赖解析或运行测试；它所用的 Python 与课程运行环境可以不同。

随后逐章运行所有离线示例。在线章节至少执行语法编译、导入检查和缺配置分支；只有提供了测试凭据并真正调用成功时才能标记为在线验证通过。

# 项目实作仓库契约

仅用于 `project`。项目是一个累计演进的实现，不是多个互不依赖的课程副本。

## 现有仓库优先

- 先读取现有 README、AGENTS、依赖与锁文件、测试/启动命令及 Git 状态；依从已有技术栈与目录，不强制 `01_*/main.py`、Python 3.12 或 uv。
- 用户明确允许基于非空仓库开发时，在确认的路径内增量修改；无关未提交改动保留。已有同名文档先读再合并，不整文件覆盖。
- 只读素材与开发目标分离。路径冲突或写入权限不明确时先确认，不能因“继续做项目”顺手改参考源码。
- 新项目按确认栈创建，锁文件用相应工具生成；不手写伪造锁文件。

## 四个持久入口

使用 `assets/project/` 模板按实情填充。下面的标题是项目结构校验器识别的**二级标题**；保留原文档其他章节，可在对应章节链接更完整的已有设计/运行文档，不重复维护整份正文。即使关键信息未确定，也应写清实际未知、阻塞与解决方式，不能留下模板标记。

| 文件 | 必须覆盖的内容 |
| --- | --- |
| `README.md` | 项目用途、当前可用范围、工具链/版本、安装与最短运行、测试/评估入口、真实运行边界、计划和进度链接 |
| `PROJECT.md` | 现行范围、用户约束、材料证据、技术取舍、里程碑与验收、授权边界、确认记录 |
| `AGENTS.md` | 结对开发/导师角色、代码与命令地图、协作分工、每步教学与验证节奏、安全及续作规则 |
| `PROGRESS.md` | 当前阶段、已执行证据、失败和阻塞、运行中作业、明确下一步 |

### PROJECT.md 必需标题

- `## 模式与目标`：明确 `project` 或“项目实作”，用户/领域、输入输出、最终结果、非目标。
- `## 需求与约束`：时间、资源、预算、数据许可/隐私、用户基础与分工；已确认和待核实分开。
- `## 材料与依据`：已读路径/链接、版本或 commit、关键事实及缺口；不写凭据。
- `## 方案与取舍`：选择什么、为何适配、放弃什么、依赖风险与退路。
- `## 里程碑与验收`：每个 M 编号的依赖、增量、必要知识、产物路径、实际命令/检查方法、通过标准、运行成本；最终验收单独明确。计划命令标为未运行，不冒称有效。
- `## 执行边界`：可写与只读路径、网络/外发、费用和时间上限、训练/服务停止条件、发布与部署授权；未授权项明确写出。
- `## 计划确认`：计划版本、用户实际确认的日期/范围、待确认变更。不能替用户批准；获准仅保存草案时标记待确认。

### AGENTS.md 必需标题

- `## 角色与协作`：确认的教学/开发分工；允许 Agent 写已授权实现，用户希望练习时保留动手机会。
- `## 项目快照`：目标、架构/数据流、代码入口、工具链及指向现行计划的链接。
- `## 逐步实施`：本步目标 → 必要知识与极小示例 → 代码映射 → 实施 → 运行 → 解释与记录；按确认分工决定等用户还是继续。
- `## 验证与安全`：真实命令、环境、成功标准与危险操作边界；静态检查不等于集成验证。
- `## 续作与进度`：先读计划、进度和已有产物/作业，再找第一个可执行的未完成步骤，避免重复昂贵工作。

### PROGRESS.md 必需标题

- `## 当前状态`：当前计划版本、里程碑状态（未开始/进行中/通过/失败/阻塞）、已交付能力和剩余验收。
- `## 执行记录`：日期、环境/版本、输入与命令、结果、证据路径、实际资源开销；首次初始化如实写“尚未执行”，不假填通过。
- `## 下一步`：下一条具体动作、所需条件、谁来做；包含等待的用户操作或运行中作业标识（如有）。

## 渐进实施与结果保留

每个里程碑增加可运行能力；各阶段共用同一源码与测试。可以依赖前期 checkpoint/数据库等，但必须记录生成、恢复和兼容性，不依赖 Agent 的聊天记忆。

开发验证只在安全临时目录或批准环境进行；记录真实数据和替身的边界。不要将大模型、私有样本、日志中的敏感字段或真实 `.env` 随代码提交。

遇到失败或用户调整计划时，先更新现行 `PROJECT.md` 的相关范围，历史执行证据保留在 `PROGRESS.md`；重做受影响的验收，不清除原失败记录来制造成功。

## 检查与最终交付

用可用的 Python 3.11+ 执行（只是运行校验器，不修改项目运行时）：

```bash
python3 <skill-path>/scripts/validate_project_repo.py <repo>
```

该脚本只检查四份文档及必要非空章节、未填模板标记，不执行任何仓库命令，也不验证用户已批准、路径是否真实可用、依赖兼容、指标达标或项目完成。

结构检查后必须按确认计划实际验证项目。逐项给出“验收条件 → 实际结果 → 证据 → 通过/失败/未验证”，包含干净环境复现或明确的外部前提。用户负责的人工验收等待反馈。需要费用、GPU、权限而未运行时，列出阻塞和恢复步骤，交付的是阶段成果，不是完整项目。

# Learn by Running Code

**先确定是学知识还是做项目，再决定怎么教、怎么做、怎样算完成。** 两种模式都采用“最小必要知识 → 代码映射 → 动手验证 → 解释结果”，不要只生成计划，也不要用完整代写替代用户期望的学习。

## 1. 先识别模式

| 模式 | 用户的主要结果 | 组织方式 | 完成口径 |
| --- | --- | --- | --- |
| `learning` 知识学习 | 能解释、修改、调试某个概念或技术 | 按知识依赖安排独立可运行章节 | 课程产物可运行；学习掌握程度另由实践与理解检查确认 |
| `project` 项目实作 | 完成有用途、有约束、可验收的项目 | 同一真实代码库上累计实现里程碑 | 已确认范围内的交付物和验收证据，不是“课程生成完了” |

- 用户明确说“系统学 asyncio”“交付一个可用系统”时直接采用对应模式并简短复述，不重复提问。
- “做 SFT”“学做 Agent”不能可靠判定意图时，先问：“你更想理解这项技术，还是做出一个具体可用的项目？也可以以项目为主，缺什么补什么。”
- 混合需求确定一个主模式：**有真实交付目标通常以 project 为主，穿插最小知识讲解**；用于理解概念的玩具最终项目仍属于 learning。不能仅因“最终项目”四个字就改模式。
- 用户已明确任务且不需要渐进教学时，不强制套用本流程。
- 中途切换模式先说明产物和验收变化，获得确认后更新计划，不直接把旧课程或旧代码重建一遍。

## 2. 按模式加载资源

共同使用 [references/teaching-method.md](references/teaching-method.md)，但其中完整逐章练习循环只强制用于 learning；project 按协作约定安排必要讲解与实践。

| 模式 | 规划前 | 写文件前 | 模板与结构校验 |
| --- | --- | --- | --- |
| learning | [curriculum-design.md](references/curriculum-design.md) | [repository-contract.md](references/repository-contract.md) | `assets/README.template.md`、`AGENTS.template.md` 及 Python 模板；`scripts/validate_learning_repo.py` |

模板必须按实情填充。结构校验器不会执行项目命令，也不能证明业务、模型效果或用户理解已经达标。

## 3. 理解目标、材料与约束

先提取已知信息，缺什么再问。项目模式允许多轮交流，每轮通常 2～4 个最影响下一步的问题，不给用户一次性填长问卷，也不预设必须问满几轮。

**共同信息：** 想获得的结果、已有知识、排除范围、目标目录、联网与外部服务限制。

**项目还需明确：**

- 给谁用、解决什么问题、输入和输出、最小可交付范围；
- 已选代码库、数据集、模型、论文或本地笔记；哪些决定固定、哪些可以建议；
- 时间、硬件、显存/存储、资金上限、数据授权与隐私；未知不等于无限制；
- 完成标准：功能/质量指标、评估数据与方法、部署或交付形式；
- 用户与 Agent 分工：用户亲手实现为主、结对完成，还是 Agent 实现并讲解。默认结对并请用户确认，不以考试阻塞用户已授权的工程推进。

用户已有材料时，请其提供**可访问的本地路径、仓库链接、文件或相关知识**；先读取目录、README、版本/依赖、关键入口及必要的小样本，再据证据规划。明确代码是只读参考还是允许修改的目标；不可访问的路径说明限制，不能声称已读，不默认扫描整个磁盘。不把私有数据、凭据或未公开代码上传到搜索/外部服务。

用户需求模糊时，不把选数据、选框架等研究工作全部推回用户：先了解目标与资源，再按项目规划参考主动检索官方文档、维护良好的实现和可复现实例，给出少量有依据的可选路线。

**澄清停止条件：** 模式、目标、最小范围、关键材料、资源边界和验收方法足以支持一份可行计划；非关键未知写成假设并给验证步骤。预算/数据授权等决定风险的未知不能靠默认值越过。

## 4. 校准资料并确认具体计划

第三方库与快速变化的 API 不能只凭记忆：核对官方文档、源码/版本与运行环境；记录来源、日期、选用版本，区分事实、设计建议和待验证假设。本地指定版本优先匹配对应文档，不把官网 main 分支当成项目已安装版本。

### learning：确认课程大纲

默认面向懂基础 Python 的初学者，Python 3.12、uv、5～7 章、中文说明、英文标识符，优先离线免费示例。课程需特殊 Python 版本时先确认，同步更新模板与环境声明，并按学习契约向校验器传入 `--python-version` 和 `--requires-python`；不要把不兼容工具链硬套入模板。

在创建文件前给出：目标与学习者画像、贯穿案例、章节表（唯一新增概念、最小知识块、依赖、运行后的可观察结果、外部要求）、最终练习与非目标、版本。等待用户确认这份具体大纲；已经明确确认过则不重复走审批。

### project：确认项目计划

给出简洁项目简报与里程碑表：

- 目标、范围/非目标、材料检查结论与尚缺信息；
- 候选方案的适配性、资源/成本估计依据、风险，推荐方案与取舍；
- 里程碑：依赖 → 新增可用能力 → 必要知识 → 实现与分工 → 产物 → 验证命令/验收指标 → 费用或外部要求；
- 首个最小端到端闭环，后续真实集成、质量验证与最终交付；
- 技术栈、允许修改的路径、数据边界、执行预算及停止条件；
- 仍需用户确认的决策与下一步。

等待用户明确确认**具体方案与边界**再创建或修改项目文件。模糊的“做一个项目”不是具体计划批准。只读检查与必要调研可以在确认前完成；用户单独要求保存规划文档时可只保存草案，但不得据此启动实现。

## 5. 从简单到复杂地推进

### learning：生成课程并引导实践

- 新目标目录必须不存在或为空；非空先报告冲突，保留用户文件与 Git 未提交修改。
- 生成 uv 项目、连续编号章节及根 `AGENTS.md`；每章从根目录独立运行，不依赖上一章留下的状态。
- 按“知识讲解 → worked example → 代码映射 → 预测与运行 → 引导实践 → 独立实践 → 检索与自我解释”教学，每章只承担一个主要新增概念。
- 关键路径不留伪代码、未定义占位函数；只为稳定复用代码建立 `shared/`。密钥仅用假值 `.env.example`。

### project：累计交付，不生成一排玩具章节

- 先检查已有仓库及工作树，保留原工具链、目录和贡献约定；新项目按需要选择栈，不强制 Python 3.12/uv。已有 `AGENTS.md` 先读取并增量合并，不覆盖原约束。
- 确认后以 `PROJECT.md` 保存现行范围、材料、决策和里程碑，`PROGRESS.md` 保存实际证据与续作点，`AGENTS.md` 保存项目协作与教学规则，README 提供运行入口。
- 每个里程碑先讲本步必要知识，再一起理解输入到输出，实施最小改动、运行验证、解释结果、记录进度。沿用同一实现，不按阶段复制多份完整源码。
- 初期可缩小数据量、功能与运行预算；替身必须标记，后续明确接入真实组件。若最终约定包含真实训练或服务，玩具结果不算交付完成。
- 已确认范围内继续推进后续可执行里程碑，不以“脚手架生成成功”结束；结对模式在需要用户动手/反馈时交接，Agent 主导模式不逐步重复询问是否继续。都不能跳过确认、费用、权限和安全门槛。
- 每个阶段可以依赖前期产物，但必须写出生成/恢复办法、版本及路径；不要求训练等有状态流程像教学章节一样彼此独立。
- 失败时定位原因、修复并复验。资源不足则标记阻塞，提供降规模、换方案或暂停选项；更改范围、预算、技术路线或验收标准须重新确认，不能悄悄降低标准。

## 6. 验证、续作与交付

**learning：** 运行 `uv lock`、`uv sync`，再用 Python 3.11+ 执行 `scripts/validate_learning_repo.py <repo>`；从干净状态逐章执行无需凭据的命令。在线章节区分语法、导入、缺配置分支与真实调用验证；无法执行必须写原因。课程生成完成不等于用户已经学会。

**project：** 用 Python 3.11+ 执行 `scripts/validate_project_repo.py <repo>` 检查文档结构；按项目本身工具链运行单元/集成/端到端或训练评估命令，并对照每项验收标准记录输入、版本、命令、结果与证据路径。不为运行校验器迁移项目运行时。结构通过不能代替实际验收。

**续作：** 先读 `AGENTS.md`、`PROJECT.md`（project）、`PROGRESS.md`、相关改动和已有产物，确认上次作业是否仍在运行；从第一个未完成且依赖满足的步骤继续，不重复已完成训练或重新询问已确认需求。不假装后台持续执行或主动提醒。

**交付报告：** 路径、最短启动/复现命令、已完成且已验证的能力、未验证/阻塞项、实际资源开销（可取得时）、下一步。项目最终逐项对照验收，必要时由用户验证；尚缺条件时交付阶段成果并明确“项目未完成”，不能包装成完成。

## 完成与安全边界

- 具体课程大纲或项目计划已确认，文档与实现、运行记录一致；
- learning 满足独立章节及导师契约；project 满足确认范围内的真实交付与验收，不只是计划、教学文件或 demo；
- 实际运行、静态检查、未验证三类结论分开，没有伪造效果、费用或用户反馈；
- 不泄露密钥，不擅自发布代码、数据、模型；付费 API、云资源、长时间训练、数据外发及部署须在明确授权的边界内，超范围先确认；
- 保留既有工作，不用“学习需要”作为重写仓库或替换用户技术选型的理由。
